## Method

- **Fetch.** `git fetch --all` (no prune), and `git fetch upstream '+refs/pull/*/head:refs/remotes/pr/*'`: 40 PR heads, #2 to #53. Nothing was deleted,
  locally or remotely.
- **Checkpoint.** `mlir/` (the MIL -> MLIR translation, the `ane` dialect, the device op sweep) was untracked; committed with the rest as wip `6009ac8ee`
  (72 files). `.gitignore` gained `training/train`, a stray binary.
- **Inventory.** 41 distinct ref tips were not in `origin/main`; 24 of them were the maximal ones (the other 17 are ancestors of those, or were already in
  `agglomerate`). Oldest commit first, each merged with `git merge --no-ff`, one at a time, no side preferred; a merge that conflicted was committed as a
  carrier with its markers as they came out. Result: 5 clean, 19 conflicted; the last carrier is `427284b66`.
- **End state of the retained conflicts**, all in one scene: 27 files, 299 marker blocks (608 counting each carrier separately), 10,200 lines inside
  conflicts. Three files took most of it: `README.md` (8 inputs), `training/Makefile` (8 inputs, 23 blocks), `training/model.h` (6 inputs). Whole-file
  conflicts came from line endings: the trunk's `training/` files are CRLF and most inputs are LF (`-X ignore-cr-at-eol` would have halved the

## Intent of each conflict, and the fix

- **Security hardening, five times** (pr/7, pr/8, pr/9, pr/13, middle/pr-5 and the omnibus pr/25: CRIT-01..04, HIGH-01..05, MED-01..06, LOW-01..04). The trunk
  already holds the checks (fread results, size_t arithmetic, dispatch_once init, calloc checks, token range); its side stays. What it lacked came in:
  HIGH-03 (release the mapping before `exec()`, resolve argv[0]), HIGH-05 (`step_ok` across accumulation steps), the audit report and diary (pr/13's complete
  versions: 19 findings, all marked fixed).
- **Token data** (pr/30, pr/38, #48 in the trunk): pr/30's `data_validation.h` checks byte count, emptiness, minimum length and vocabulary range and has a
  C test (`test_data_validation`, 18/18); it replaces the short-dataset guards in `train_large`, `train_large_ane` and `training_dynamic`, keeping the trunk's
  configurable data path. The descriptor closes right after `mmap`, so the `close()` before `exec()` was removed.
- **ANE SDK** (pr/18): multi-input kernels. `compile_kern_mil_multi` has the new signature; `compile_kern_mil_w` keeps its own for its 48 call sites; `Kern`
  keeps `ioIn` as `inputs[0]`. The SDK (`layers/`), its tests and `benchmark_ane` came in, with the weights-as-tensors generators beside the baked ones in
  `stories_mil.h`. pr/18's rewrite of `train_large.m` (weights as input tensors) was not taken: `training_dynamic/` is the same idea, in the trunk.
- **MIL syntax variants** (pr/6 and the same in pr/25: `program(1.0)`, `ios16`, `tensor<string, []>` scalars, for M1/M2): not taken in the generators; the
  trunk's syntax runs on this M3 Pro, the variant was not trialled. pr/25's `g_fp16_io` branches and GQA functions, which its inference engine needs, were
  transplanted. pr/35's runtime chip detection (`ane_get_mil_version()`) came in.
- **Makefile**: one file with every target the inputs added (SDK, research probes, M5 suites, data validation, `setup`/`data`, `verify-flags`,
  `check-deprecated`); 26 targets that exist in no single input.
- **`inference/`** (pr/26, then pr/25's Metal, Q4 and HTTP extension): pr/25's files. **READMEs**: the trunk's, plus the sections of pr/16 and pr/28 and
  the SDK section. **`.gitignore`**: one list (every branch had added its own to a trunk that had none).

The failures of the first run were a regression of the merge, found by this comparison: `test_rmsnorm_bwd`, `test_classifier` and the SDK tests failed with
`verifyBundleAtPath: invalid model`. Cause: **MED-02**, the `ANE_<pid>_<seq>_<hash>` directory name in `stories_io.h` and `ane_runtime.h` (it comes from pr/8, the MED findings, and pr/13 on top of it). On macOS 27.2.1
ANECompilerService verifies the bundle against the hash-named directory directly under the temp directory; a prefix fails, and so does a unique parent
directory (tried). Reverted, with a comment in both files. The audit report and diary still list MED-02 as fixed.

Not run: `train_large`, `train_large_ane`, `train_opt`, `train_double_buffer` and `training_dynamic` (no model or token files here; on 27.2.1 the static
trainers fail at layer 0 on upstream main too, by the bundle rule in `mlir/README.md`), the inference binary (needs the Qwen weights), the Metal and Q4 paths,
the M5 suites, and every `training/test_*.m` probe of March 2026 beyond the three above (older than 30 days, so not current tests; they build).
